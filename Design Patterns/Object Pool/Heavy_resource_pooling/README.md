# Report Generation System - Object Pool Design Pattern

## 📖 Project Overview
This module demonstrates the **Object Pool Design Pattern** within a Spring Boot application. It simulates a heavy resource management system where initializing an `ExportEngine` (e.g., for PDF rendering or legacy system connections) is costly in terms of time and CPU.

Instead of instantiating a new engine for every REST request, the application maintains a thread-safe "pool" of reusable engines. Requests borrow an engine, perform their task, and return the engine to the pool, drastically improving response times after the initial warmup phase.

## 🛠️ Tech Stack
* Java 17+
* Spring Boot 3.x
* Maven

## 📂 Project Structure
* **model:** Contains the `ExportEngine`, simulating a resource that takes 2 seconds to initialize.
* **pattern:** Contains the core implementations: the generic, thread-safe `ObjectPool<T>` and the specific `ExportEnginePool`.
* **controller:** The REST API endpoint that borrows the engine, executes business logic, and safely returns the engine via a `finally` block.

## 📡 API Reference

### 1. Generate Report
**Endpoint:** `GET /api/reports/generate`  
**Query Parameter:** `data` (String. The content to be reported).  
**Description:** Borrows an engine from the pool to process the data. *Note: The first 3 requests will take ~2 seconds each as the pool lazily initializes. Subsequent requests will take <10ms as objects are reused.*

**Example Request:**
```http
GET /api/reports/generate?data=QuarterlyFinancials
```
**Example Response:**
```json
{
  "message": "Report [QuarterlyFinancials] generated by Engine-a1b2c3d4",
  "engineUsed": "a1b2c3d4",
  "timeTakenMs": 4,
  "status": "SUCCESS"
}
```

### 2. Check Pool Status
**Endpoint:** `GET /api/reports/pool-status`  
**Query Parameter:** `data` (String. The content to be reported).  
**Description:** Retrieves the current state and utilization metrics of the Object Pool.

**Example Request:**
```http
GET /api/reports/pool-status
```

**Example Response:**
```json
{
  {
  "objectsCurrentlyInPool": 3,
  "maxCapacity": 3,
  "totalObjectsCreated": 3,
  "objectsCurrentlyInUse": 0
}
}
```

## 🧠 Object Pool Pattern Implementation Details
The Object Pool pattern manages the instantiation and lifecycle of heavy objects. In this system:

* **The Reusable Object (`ExportEngine`):** Encapsulates an expensive initialization process. It contains no state related to specific requests, making it safe to reuse across different clients sequentially.
* **The Abstract Pool (`ObjectPool<T>`):** Manages a thread-safe `ConcurrentLinkedQueue`. It keeps track of the maximum allowed objects. The `borrowObject()` method attempts to retrieve an existing object, creates a new one if the pool is empty but under capacity, or throws an exception if exhausted. The `returnObject()` method pushes the object back into the queue.
* **The Concrete Pool (`ExportEnginePool`):** Extends the generic pool and implements the `create()` method specifically for `ExportEngine`s. Registered as a Spring `@Component`.
* **The Client Protocol (`ReportController`):** The most critical rule of using an Object Pool is that the client **must** return the object. This is strictly enforced by placing the `enginePool.returnObject(engine)` call inside a `finally` block, ensuring the resource is never leaked, even if the processing throws an exception.
